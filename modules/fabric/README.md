# Fabric infrastructure modules

`capacity/main.bicep` provisions an Azure-billed Microsoft Fabric capacity with the stable `2023-11-01` API. This offering starts at F64 and requires explicit capacity administrator identities. F64 is a sizing/licensing baseline, not evidence that it is sufficient for a particular workload. Capacity administrators, workspace roles, Azure resource roles and per-user Power BI licenses are different controls. [Fabric licensing](https://learn.microsoft.com/fabric/enterprise/licenses).

`workspace-private-link/main.bicep` binds an **existing** Fabric workspace to `Microsoft.Fabric/privateLinkServicesForFabric@2024-06-01` and creates a private endpoint with group `workspace`. It references the approved endpoint subnet and existing `privatelink.fabric.microsoft.com` zone; it never creates/adopts a shared VNet, subnet, DNS zone or VNet link. Reserve at least ten addresses per workspace endpoint and validate the workspace's F-capacity assignment, tenant feature setting, provider registration and permissions first. The Fabric Private Link service resource does not support tags; the endpoint receives normal ownership tags. [Microsoft setup instructions](https://learn.microsoft.com/fabric/security/security-workspace-level-private-links-set-up).

ARM deploys the capacity and optional workspace inbound connection. Fabric workspaces, items, workspace identity, role assignments, source connections, managed private endpoints, network communication policy and deployment pipelines use their documented Fabric APIs. The Azure capacity resource ID is not the Fabric capacity UUID. Never pass the Azure resource ID as a Fabric `capacityId`.

Private endpoint creation does not deny public traffic. Verify approval, DNS and connectivity from the approved private runner and client networks, then separately set and read back the workspace communication policy. Inbound workspace Private Link does not create private outbound access to source systems. Fabric managed private endpoints and Data Factory gateway/data-connection-rule support are workload-specific. [Managed endpoint overview](https://learn.microsoft.com/fabric/security/security-managed-private-endpoints-overview).

Fabric deployment pipelines currently cannot connect to a stage workspace configured to deny public access. Select and qualify a compatible deployment approach before applying that policy; this module never changes a workspace firewall to enable promotion. [Workspace Private Link limitations](https://learn.microsoft.com/fabric/security/security-workspace-level-private-links-support).

`private-adls-source/main.bicep` is an optional source-owned example, outside the default capacity composition. It reuses the reviewed private ADLS module with shared keys/public access disabled, creates blob/dfs endpoints on approved existing infrastructure, and grants the observed workspace identity only `Storage Blob Data Reader` on the `landing` container. The example creates `landing` and `curated` containers; it does not populate data or grant write access. Customer-network endpoints let private agents/clients reach the source. Fabric Spark additionally needs approved managed private endpoints; Data Factory connections need a supported gateway route. The module intentionally does not enable `AzureServices` bypass or create account keys, SQL passwords or a purported universal private connector.

These modules compile locally; ARM validation/What-If, F-capacity quota and region checks, Fabric API acceptance, DNS/private-network verification, cost review and protected environment approval are separate gates. See [the workload guide](../../workloads/fabric/README.md) for the end-to-end flow and remaining onboarding.
